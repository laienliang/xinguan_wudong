# 测试执行指南

## 快速开始

### 1. 运行所有测试
```bash
npm test
```

### 2. 生成覆盖率报告
```bash
npm run cov
```

### 3. 使用自动化脚本
```bash
# 运行完整测试并生成报告
./run-tests.sh

# 只生成覆盖率报告
./generate-coverage.sh
```

## 测试分类

### 单元测试 (Unit Tests)
测试单个函数/方法的业务逻辑

```bash
npm test -- test/unit
```

**已实现的单元测试:**
- `test/unit/shop/goods.service.test.ts` - 商品服务业务逻辑

### 集成测试 (Integration Tests)
测试 API 接口的端到端功能

```bash
npm test -- test/integration
```

**已实现的集成测试:**
- Shop 模块: category, goods, order, boundary, consistency
- Food 模块: restaurant
- Hotel 模块: hotel
- Tour 模块: scenic
- Community 模块: post
- 跨模块测试: multi-tenant, performance, security

### 按模块运行测试

```bash
# 商品模块
npm test -- shop

# 餐饮模块
npm test -- food

# 住宿模块
npm test -- hotel

# 门票模块
npm test -- tour

# 社区模块
npm test -- community
```

## 常见问题

### 1. 测试失败提示找不到模块
确保已安装依赖:
```bash
npm install
```

### 2. 测试超时
增加超时时间配置在 `jest.config.js`:
```javascript
testTimeout: 30000
```

### 3. 数据库连接失败
检查数据库配置和服务状态:
```bash
# 检查 MySQL 是否运行
ps aux | grep mysql
```

### 4. 端口冲突
确保后端服务运行在正确端口:
```bash
lsof -i :8001
```

## 最佳实践

### 编写测试用例
1. **AAA 模式**: Arrange (准备) → Act (执行) → Assert (断言)
2. **命名清晰**: `should do something when condition`
3. **独立性**: 每个测试独立运行
4. **可重复**: 测试结果稳定

### 测试数据
1. 使用 **TestDataFactory** 创建测试数据
2. 使用 **MockDataGenerator** 生成随机数据
3. 测试后清理数据

### 断言建议
1. 具体明确的断言
2. 测试预期行为而非实现细节
3. 一个测试一个断言（原则上）
